# Interior two-tier rhythm and max-shelves / min-segment packing

- **Status**: accepted
- **Date**: 2026-05-12
- **Context**: Roadmap items need a transition-based vertical rhythm (dense lower / wider upper air gaps) and a packing mode driven by a minimum vertical segment height without hand-picking shelf counts.
- **Decision**:
  - Add `InteriorSpec::TwoTierRhythmShelves` with `transition_y_mm` (strictly between `0` and inner `height_mm`), `gap_lower_mm`, `gap_upper_mm`, optional `top_reserve_mm` (default `0`), optional `shelf_thickness_mm`. Shelf bottoms are built bottom-up: floor→first gap is `gap_lower_mm`; after each shelf, the next air gap uses `gap_lower_mm` while that shelf’s top is strictly below `transition_y_mm`, otherwise `gap_upper_mm` (must be ≥ `gap_lower_mm`). Packing stops when the next shelf would leave less than the core minimum ceiling air gap (`0.01` mm) under `height_mm − top_reserve_mm`.
  - Add `InteriorSpec::MaxShelvesMinSegmentShelves` with `min_vertical_segment_mm` (≥ same minimum air gap), optional `bottom_reserve_mm` / `top_reserve_mm` (default `0`), optional `shelf_thickness_mm`, optional `shelf_count`. Let `band_mm = height_mm − bottom_reserve_mm − top_reserve_mm`. **Maximum** shelf count `n_max` is the largest integer `n ≥ 1` with `band_mm − n·t ≥ (n+1)·m` for shelf thickness `t` and segment minimum `m`. Omitted `shelf_count` uses `n_max`; when set, `shelf_count` must satisfy `1 ≤ shelf_count ≤ n_max`. Shelf bottoms equal [`equal_spacing_shelf_bottoms_mm`](../../furnigen-core/src/interior_shelves.rs) on `band_mm` with the chosen `n`, shifted by `+ bottom_reserve_mm`.
- **Alternatives considered**: Continuous optimization for two-tier (user-chosen shelf count with least-squares gaps) — deferred: greedy rule is simpler and matches the roadmap wording. For max-shelves: “target count then widen gaps only” without a hard `m` on every segment — rejected for v1; explicit `shelf_count` already widens gaps while keeping `m` as a floor on every equal segment.
- **Consequences**: Preview mesh, BOM/panels, WASM JSON entrypoints, web Zod, and golden fixtures must include the new `type` strings (`two_tier_rhythm_shelves`, `max_shelves_min_segment_shelves`). UI exposes the new fields; invalid combinations (e.g. `gap_upper` < `gap_lower`, `shelf_count` > `n_max`) fail `validate_wardrobe_spec` / `parse_wardrobe_spec_json`.
